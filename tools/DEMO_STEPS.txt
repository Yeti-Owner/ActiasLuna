================================================================
  MOTH DEMO - STEP BY STEP  (keep this; the demo Wi-Fi has no internet)
  The demo Wi-Fi is named  WATCHING-YOU  (NOT "EmoryGuest" / "eduroam").
================================================================

WHAT YOU HAVE
  - Callum's server + 3D dashboard that marks the ESP32 boards and tracks a phone.
  - Your Uno Q white button, which toggles SIMULATED decoy phones in that same 3D view.
  - A board SIMULATOR, so you can test the whole thing with NO hardware.

The decoys are simulated and display-only: they appear in the view, nothing is sent over the air.

ONE-TIME SETUP (do this now, while you still have internet):
  1. Open a terminal in the project folder:
       cd C:\Users\nicho\OneDrive\Documents\GitHub\ActiasLuna
  2. Install the server's requirement (needs internet - do it BEFORE the demo Wi-Fi):
       py -m pip install -r requirements.txt
  (numpy is the main one. If it says "already satisfied", you're set.)

----------------------------------------------------------------
  A) PRACTICE RUN - no boards, no demo Wi-Fi  (do this first!)
----------------------------------------------------------------
  1. Plug the Uno Q into the laptop by USB.
  2. In the terminal:
       py tools/demo_run.py --sim --button
  3. Open a browser to:   http://127.0.0.1:8080
  4. Within a few seconds you should see 3 boards and a moving "SimPhone".
     -> that is the Wi-Fi watching/tracking working (on fake data).
  5. Press the white button on the Uno Q.
     -> simulated decoys appear scattered in the room.
     Press it again -> they all disappear.
  6. When done, click the terminal and press  Ctrl+C  to stop everything.

  No button yet? Run:  py tools/demo_run.py --sim
  and toggle the decoys by opening this URL in the browser:
       http://127.0.0.1:8080/api/crowd       (each visit flips them on/off)

----------------------------------------------------------------
  B) REAL RUN - actual ESP32 boards on "WATCHING-YOU"
----------------------------------------------------------------
  Needs (Callum's side): the 3 ESP32-S3 boards flashed (1 AP + 2 RX) and powered,
  config/network.json set, and secrets generated. If the boards aren't flashed yet,
  use the PRACTICE RUN above - it exercises the same server and 3D view.

  1. Power on the ESP32 boards.
  2. Join the laptop to the  WATCHING-YOU  network.
  3. Plug the Uno Q into the laptop by USB.
  4. In the terminal:
       py tools/demo_run.py --button
  5. Open:   http://127.0.0.1:8080
     - The boards appear as they come online. A phone that joins WATCHING-YOU
       shows up and can be tracked (do the calibration walk from the phone page).
     - "No signal / empty map" means the boards or the laptop aren't on the demo
       Wi-Fi yet, OR the boards aren't flashed/configured. That is the real detection
       side (Callum's), separate from your decoys.
  6. Press the white button to show/hide your decoys among the real markers.
  7. Ctrl+C in the terminal to stop.

----------------------------------------------------------------
  TROUBLESHOOTING (offline-safe)
----------------------------------------------------------------
  - "No module named numpy"  -> you skipped setup; run the pip install (needs internet).
  - Dashboard 3D view is blank -> it uses bundled three.js and works offline; reload once.
  - White button does nothing  -> is the Uno Q plugged in by USB? Only ONE program can
      use the button at a time (don't run two button bridges / don't keep Serial Monitor open).
  - Map stays empty in the REAL run -> boards/laptop not on WATCHING-YOU, or boards not flashed.
  - Decoys appear but map is empty -> that's expected; decoys are simulated and do NOT need signal.

  The dashboard is always at:   http://127.0.0.1:8080/
================================================================

================================================================
  REAL BOARDS DON'T SHOW UP  (button works, map empty)
================================================================
The button works over USB and the dashboard is localhost, so those can work even
when the boards can't reach the laptop. The boards only appear when the laptop is
truly ON the demo subnet. Check these IN ORDER:

  1) JOIN the network, then prove you got a demo address:
       - Join WATCHING-YOU in Windows Wi-Fi (the password is whatever Callum
         flashed into the boards - ask him if "WATCHING-YOU" won't accept it).
       - Open a terminal and run:   ipconfig
       - The Wi-Fi adapter MUST show   IPv4 Address . . . 192.168.4.x
         * 192.168.4.x  -> good, go to step 2.
         * 169.254.x.x  -> you joined but got no address (AP/DHCP not ready):
                           wait 20 s and reconnect, or the AP board isn't up.
         * anything else (172.x, 10.x) -> Windows stayed on the OTHER Wi-Fi.
                           Disconnect that one and connect ONLY to WATCHING-YOU.

  2) Run the server by itself so you can read its messages:
       py server/luna_server.py
     Watch the console:
       "laptop on demo Wi-Fi as 192.168.4.x"  -> good; boards should appear in a
                                                 few seconds at http://127.0.0.1:8080
       "laptop is NOT on the demo Wi-Fi"       -> back to step 1, you're not on the subnet.

  3) Still empty but step 2 said you're ON the demo Wi-Fi?
     a) Windows Firewall may be dropping the boards' replies. Open PowerShell
        **as Administrator** and run (one line):
          New-NetFirewallRule -DisplayName "Moth boards" -Direction Inbound -Action Allow -Protocol UDP -LocalPort 5006,5007
        Then set the demo Wi-Fi to a Private network:
          Get-NetConnectionProfile            (note the demo Wi-Fi's InterfaceIndex)
          Set-NetConnectionProfile -InterfaceIndex <that number> -NetworkCategory Private
        Re-run the server.
     b) Check the boards themselves (Callum's side): all 3 powered? The AP board
        (A) makes the network; if WATCHING-YOU exists, A is up, but B and C must
        also be powered and joined. Were they flashed with THIS network's password?

  4) Confirm packets are arriving at all: the dashboard's node/board count stays 0
     if nothing reaches UDP 5007. If step 1 and 2 are green and it's still 0, it's
     almost certainly the firewall (3a) or the boards (3b), not your laptop setup.
